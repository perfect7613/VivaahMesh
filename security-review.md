# VivaahMesh security review

Reviewed on 25 November 2026 against the OWASP Top 10 (2025). The review followed requests from Telegram and the public link pages through the Next.js handlers, Postgres migrations, agent tools, provider clients and result worker. It also covered operational scripts, GitHub Actions, deployment manifests and the npm lockfile. Severity below reflects the impact before remediation. [OWASP Top 10](https://owasp.org/Top10/2025/)

## Findings and fixes

| Severity | Finding | Change and verification |
| --- | --- | --- |
| High | A household invitation could confer management permissions through a self-selected parent label. Repeat joins could change membership. | Creation atomically writes the creator membership and both families. Per-account limits cover creation and invitation lookups. The join transaction keeps the original household and requires couple approval for parent management. Telegram group binding also verifies group administration and wedding membership. The database fixture covers repeats, attempted cross-household joins, privilege grants and revocation. See [onboarding migration](supabase/migrations/20261125160100_onboarding_access.sql#L20) and [privilege tests](supabase/tests/onboarding_access.sql). |
| High | Private family context could reach the shared agent feed, another conversation, or a public search provider. Model-selected URLs could cause the application to make outbound requests. | Agent history is scoped by wedding and member. Private turns have a restricted tool set. Public search requires an explicit command and page reads are confined to results of that search through the configured provider. The application no longer fetches a model-selected destination directly. See [agent boundaries](web/src/lib/server/agent-scope.ts#L5) and [search tests](web/tests/agent-web.test.mjs). |
| High | Vendor and guest bearer links exposed more authority than the individual viewer needed. Planner operations relied on a self-reported role and some writes did not bind every object to the same wedding. | The planner enforces the delegated role and narrows link visibility. Guest and vendor links expire after one year, can be rotated, and canceling a vendor invalidates its link. The new service-only database functions recheck ownership at write time. Vendor cancellation records recovery tasks in the same transaction and RSVP retries preserve the original result. See [planner service](web/src/lib/server/lifecycle.ts) and [lifecycle database tests](supabase/tests/lifecycle_access.sql). |
| High | The browser SDK installed an unused native audio dependency with a high-severity advisory. | The application installs only the browser distribution and its license from the integrity-pinned upstream SDK. The archive is reproducible, the lockfile points to the official registry, and CI checks for high or critical npm advisories. See [packaging source](web/vendor/package-sarvam-browser.py#L12) and [CI](.github/workflows/ci.yml). |
| High | Paid provider calls, transcription and agent runs could be repeated without a durable limit. Browser evidence and callbacks carried unnecessary identifiers. | Database-backed quotas cover interactive agents, voice uploads and outbound dialing. Provider timestamps and opaque references bind browser evidence to its consent window. The callback projection and migration remove echoed credentials and telephony metadata. See [voice request limits](web/src/lib/server/voice-request.ts#L11), [browser calls](web/src/lib/server/browser-calls.ts) and [migration](supabase/migrations/20261125160200_voice_request_limits.sql). |
| Medium | A public realtime topic was derived from the wedding ID and broadcast the event kind. | Membership-checked views receive an opaque, keyed topic. Notifications contain an empty payload. Clients throttle notifications and refetch data under their own authorization. See [publisher](web/src/lib/server/wedding-live.ts#L6) and [tests](web/tests/wedding-live.test.mjs). |
| Medium | Some token-bearing pages loaded the Telegram script, authenticated responses could be cached, and provider errors could include sensitive content. | The Telegram script loads at the Mini App entry. Protected responses set private cache controls, bearer pages suppress referrers, and operational errors use bounded status information. See [page headers](web/next.config.ts), [Telegram entry](web/src/app/tg/TelegramEntry.tsx) and [authenticated handler](web/src/lib/server/route.ts). |
| Medium | Recovery could interpret an invalid dry-run option as a request to change state or rely on a fallback switch value. | The privileged endpoint validates a bounded body and requires an authoritative remote Flagsmith value before replay. Errors and an unconfirmed switch halt recovery. The approval workflow targets one saved call. See [recovery handler](web/src/app/api/ops/recover/route.ts#L17) and [integration tests](web/tests/recovery.integration.ts). |
| Medium | Unbounded inputs, default workflow permissions and mutable build references increased the impact of malformed requests and compromised dependencies. | Application routes limit input sizes, check types, and validate identifiers. GitHub Actions dependencies are pinned, checkout credentials are dropped and the heartbeat token has no repository permissions. The worker uses a digest-pinned base, a numeric unprivileged identity, dropped capabilities and a read-only filesystem. See [request reader](web/src/lib/server/request-body.ts), [workflow](.github/workflows/heartbeat.yml) and [deployment](ops/result-worker/deployment.yaml). |

## Coverage

| OWASP 2025 category | Boundaries examined |
| --- | --- |
| A01 Broken Access Control | Couple, delegated parent, wedding, household, guest and vendor permissions. Reviewed database grants, service-only RPCs, private conversations, and public-search URL handling. |
| A02 Security Misconfiguration | Browser and API headers, bearer-link referrers, deployment identity, filesystem permissions, CI tokens and credentialed redirects. |
| A03 Software Supply Chain Failures | npm dependency tree, SDK provenance and integrity, worker base image, pinned Actions and the PostgREST download checksum. |
| A04 Cryptographic Failures | Telegram signatures, freshness and timing-safe comparisons, invite entropy, provider callbacks and server-derived realtime topics. |
| A05 Injection | Structured PostgREST operations, database routines, validation of generated UI strings, Telegram output escaping, and model tool arguments. |
| A06 Insecure Design | Consent, provider budgets, web lookup boundaries, data minimization and separation of family input from shared decisions. |
| A07 Authentication Failures | Signed Mini App requests, duplicate Telegram fields, webhook/setup secrets, development bypass conditions and token-scoped routes. |
| A08 Software or Data Integrity Failures | Callback scope, source attribution after edits, duplicate writes, replay, reservation concurrency and artifact digests. |
| A09 Security Logging and Alerting Failures | Raw provider and database error content, heartbeat output, deduplicated incident evidence, approval and replay reporting. |
| A10 Mishandling of Exceptional Conditions | Bounded streams, invalid JSON, quota database failure, unconfirmed switch state, provider timeouts and recovery retries. |

## Rollout and verification

Apply the new Supabase migrations before deploying the matching web app and worker. The onboarding migration preserves existing parent grants and invite links. Couples can review and revoke parent access in the app. Previously shared notes and external provider copies need a separate retention review. Rotate the optional server-side realtime secret to invalidate previously issued topics.

Checks completed on the reviewed source:

- A clean Node 22 installation, ESLint, TypeScript and the optimized Next.js build passed. Vitest passed 142 unit tests. The PostgreSQL/PostgREST suite passed both integration tests and its SQL privilege and concurrency assertions.
- npm audit returned zero advisories. OSV-Scanner reported zero matches from the lockfile. Trivy reported zero findings in the production npm lockfile scan and in the worker Dockerfile and Kubernetes Deployment configuration. The replacement Alpine worker base on Linux AMD64 had zero high or critical OS package findings.
- Gitleaks scanned the tracked source and reachable commit history with default detectors and an additional NudgeBee key pattern. Neither scan reported a secret. Actionlint passed on all three workflows.
- HTTP checks of the production build confirmed private, no-store responses, no referrer, and frame embedding blocked on the four bearer-page families. The Telegram script loaded on the Mini App entry alone among these tested pages. An unauthenticated request to the member endpoint returned 401.

The verification suite uses disposable PostgreSQL and PostgREST, simulated Telegram identities and controlled provider responses. It covers authorization, quotas, duplicate writes and two-household convergence. Actual calls, provider-side retention, production database contents, Kubernetes RBAC and the NudgeBee human approval workflow require separate deployment evidence.
